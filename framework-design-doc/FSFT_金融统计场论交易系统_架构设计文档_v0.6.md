## 1. 设计目标与定位

### 1.1 总体目标

构建一个以**金融统计场论（Financial Statistical Field Theory, FSFT）**&#x4E3A;动力学先验的期货交易系统，实现：

1. tick 数据流隐藏模式的识别（微观涨落结构）；
2. 市场临界状态（变盘）预警；
3. 行情级别（空间上下界）的概率化区间估计；
4. 支撑止盈、止损与撤单决策的实时风险度量；
5. 分钟级端到端推理与市场状态解释。

远期愿景：成为期货交易领域的类 Aladdin 基础框架——即以统一的"风险与状态语言"为核心的引擎，而非以方向预测为核心的引擎。

### 1.2 定位声明（学术严谨性边界）

- 本系统中，"量子""相变""序参量""对称破缺"等术语均为**数学类比意义上的操作化定义**，借用的是统计场论与量子场论的**泛函积分数学体系**（路径积分、生成泛函、有效作用量、重整化群）与统计物理的临界现象理论。本系统**不主张金融市场存在任何物理量子效应**。
- 所有借用概念必须在数据中落地为**可测量、可证伪的操作化定义**；无法操作化的概念（如规范场的"联络"、共形对称性）不进入本期架构，仅列为远期探索方向。
- 本系统有效性以**样本外统计检验与风险承诺兑现检验**为唯一判据（见第 5 章评价体系）。

### 1.3 非目标（Non-Goals）

- 不做方向性点预测承诺（高频方向预测信噪比极低，不在本架构承诺范围内）；
- 不追求毫秒级实盘高频做市，推理节拍为分钟级（次高频）；
- LLM 不参与原始行情数据的表征学习与预测生成；
- 不使用真实量子硬件（量子启发算法如需，亦在经典硬件上运行）。

## 2. 核心术语的操作化定义

| 术语       | 操作化定义                                            | 可观测判据                 |
| -------- | ------------------------------------------------ | --------------------- |
| 市场场      | 价格与波动率构成的随机场 φ(x,t)；x 为合约/期限维度，t 为时间维度           | 价格期限结构、已实现波动率曲面       |
| 涨落       | 对数收益率序列相对条件均值的偏离，含重尾非高斯成分                        | 超额峰度、幂律尾部指数           |
| 长程关联     | 波动率自相关的幂律衰减（非"长程序"，不主张严格长程序存在）                   | 自相关函数衰减指数、Hurst 指数    |
| 序参量 φ    | 涨跌方向不对称度（或截面吸收比 absorption ratio 等，立项时唯一选定并冻结定义） | φ 持续偏离零且超出其历史分位阈值     |
| 对称性（唯象）  | 时间平移下稳态收益分布的无漂移性质                                | 滚动窗口漂移显著性检验           |
| 对称破缺（唯象） | 趋势 regime 的建立，即 φ 显著偏离零并伴随关联长度发散                 | φ 显著性 + 关联函数拟合的关联长度增大 |
| 临界点/变盘预警 | 临界慢化信号：滞后一阶自相关与方差的同步抬升                           | 预警指标超阈值（阈值在训练段标定）     |
| 重整化群（RG） | tick→秒→分钟的多尺度粗粒化流程及其参数流                          | 各尺度上有效参数的漂移轨迹         |

> 纪律：上表定义在立项时冻结。任何修改须经版本评审并重新执行全部样本外检验。

├─────────────────────────────────────────────────────┤

| 接口     | 方向        | 内容                                    | 约束                            |
| ------ | --------- | ------------------------------------- | ----------------------------- |

## 4. 各层职责与职责边界

### 4.1 L0 数据与基础设施层

- 期货 tick 数据接入（时间戳统一至交易所时标，处理夜盘跨日）；
- 异常值与错误报价清洗（规则化、可审计，清洗规则版本化存档）；
- RG 粗粒化管线：tick→秒→分钟多尺度序列生成，保留各尺度统计量；
- **评估管线（Evaluation Harness）**：独立于模型开发团队维护，详见第 5 章；
- 全链路审计日志：数据版本、参数版本、信号版本可回溯。

### 4.2 L1 动力学层（FSFT 引擎）

#### 4.2.1 架构界定：随机隐状态空间模型

L1 的本体是**随机隐状态空间模型**（ stochastic state-space model ），函数形式由场论演化方程锁死，数据仅负责标定物理参数：

- **隐状态** h(t) = (T_eff, ξ, φ, ...)：有效温度、关联长度、序参量等场论状态变量（第 2 章）；
- **转移方程（漂移-扩散结构）**：

  dh(t) = A_FSFT(h; θ_phys) dt + Σ(h; θ_phys) dW(t) + dJ(t)

  其中漂移项 A_FSFT 由场论有效作用量的变分方程给出（对称破缺势的非线性回复形式），扩散项 Σ 刻画涨落强度（与 T_eff 挂钩），dJ 为可选跳跃项（刻画突变型变盘）；
- **观测方程**：

  r(t) = C·h(t) + ε(t),  ε ~ 重尾分布（Student-t / 稳定分布）

  r 为多尺度收益率向量（RG 管线输出），ε 为微观结构噪声。

**阶段一实现（零神经网络）**：Unscented Kalman Filter / 粒子滤波直接推断隐状态与参数 θ_phys。物理项全部锁死，不允许任何可学习的自由函数。

**阶段二升级（Neural SDE）**：漂移与扩散函数中**场论解释不了的残差分量**用小型 MLP 参数化：

dh = [A_FSFT(h; θ_phys) + g_ω(h, u)] dt + [Σ(h; θ_phys) + σ_ψ(h)] dW

约束纪律：物理项 θ_phys 冻结，仅残差项 g_ω、σ_ψ 可学；残差项输出范数施加正则上限，防止残差吞噬物理结构（即"物理为主、残差为辅"的不对称约束）。

#### 4.2.2 职责

1. 波动率/价格场的动力学推断：滤波/平滑估计隐状态轨迹与参数；
2. 输出可解释的状态变量——本架构相对纯黑箱模型的核心差异化资产；
3. 临界预警：基于临界慢化（方差与滞后自相关同步抬升）与序参量行为生成变盘预警信号；
4. 风险度量：基于场论分布（幂律尾）的 VaR/ES 估计；
5. 行情级别估计：以概率分布形式输出空间上下界（分位数区间），**禁止输出点预测承诺**。

**边界：** L1 参数只能由训练段数据标定，不允许在评估段/封存段上做任何手动调参。

### 4.3 L2 学习与推断层（SSM 主干 + 物理结构继承）

#### 4.3.1 架构选型论证（函数族同构原则）

选型标准：**网络函数族与 FSFT 动力学函数族的同构度**——同构度越高，物理约束以"结构"而非"惩罚项"嵌入，模型越小、越稳、越可解释。对标结果：

| 候选架构                        | 连续时间                    | 长记忆效率              | 物理约束嵌入                                            | 判定                       |
| --------------------------- | ----------------------- | ------------------ | ------------------------------------------------- | ------------------------ |
| Transformer / iTransformer  | ✗ 等间隔假设                 | O(L²)，tick 序列代价高   | 仅损失惩罚项                                            | **排除**：全局注意力与场论局域动力学先验冲突 |
| TCN                         | △ 离散                    | 膨胀因果卷积，效率好         | 时间不光滑，仅近似                                         | **保留为评价协议强基线**（诚实对照组）    |
| **结构化 SSM（S4 式 / 对角化 SSM）** | ✓ 原生连续时间离散化，支持不等间隔 tick | O(L)，压缩记忆天然表达幂律衰减核 | **高同构**：线性 SSM ↔ 自由场二次型作用量离散化；输入依赖门控 ↔ 相互作用项/对称破缺 | **首选主干**                 |
| Neural SDE                  | ✓ 完全原生                  | 依赖求解器              | **完全同构**：即场论演化方程本体                                | L1 的阶段二形态（见 4.2.1）       |

理论对应（函数空间层面，非隐喻）：自由场论（二次拉格朗日量）↔ 线性状态空间模型（高斯、卡尔曼可解）；相互作用项 ↔ SSM 非线性门控；涨落项 ↔ 过程噪声/扩散项。

#### 4.3.2 组成与约束嵌入

- **主干**：结构化 SSM，输入为 L0 多尺度序列 ⊕ L1 状态变量快照；
- **三级约束嵌入**：① 特征级——L1 状态变量作为输入；② 结构级——SSM 初始化与离散化参数继承 L1 标定的关联衰减指数（物理参数向网络结构的直接传递）；③ 损失级——预测分布尾部指数与场论幂律尾匹配的惩罚项；
- **头部**：分位数集合输出（支撑覆盖率与 pinball loss 评价），输出预测分布而非点值；
- **规模纪律**：参数量上限写入评价协议（建议 ≤ 1M），防止小模型退化为黑箱；
- **职责**：学习 L1 的**残差**（微观结构噪声等场论未解释部分），分钟级推断，输出服务止盈止损决策的概率化区间。

**边界：** L2 的输出必须保留不确定性表达；禁止蒸馏成单一方向信号输出给执行层。

### 4.5 落地实现技术选型

#### 4.5.1 总原则

> **每一层只引入"经过验证的数值原语"，不引入"完整的黑箱框架"；凡是写入评价协议的模型结构，代码必须完全自有。**

借力点只允许选在数值原语（autograd、SDE/ODE 求解器、滤波器），不允许选在模型架构（不 fork 任何完整模型仓库做二次开发）。理由：现成模型（TCN、S4、Mamba 开源实现）以等间隔采样、无物理参数接口为前提，二次开发需改动其骨架，产物既非原作者验证过的模型、也非完全可控的自有代码，审计性受损（违反第 6 章硬性要求）。

#### 4.5.2 排除项：梯度提升树（LightGBM/XGBoost）不作为模型载体

结构性硬冲突，非偏好问题：

1. **无隐状态概念**：GBDT 是静态映射 f(x)→y，无状态推进方程，无法表达 L1+L2 的状态空间本体；
2. **物理约束无处安放**：树对输入是分段常数函数，时间导数几乎处处为零，PINN 式残差约束在数学上失效；
3. **分布输出非原生**：各分位数独立拟合，无联合分布结构，无法挂钩幂律尾参数，评价体系支柱 2 将系统性失分。

**其合法位置**：仅作为评价协议中的 tabular 路线对照基线（"对手"而非"载体"）。

#### 4.5.3 分层实现方案

| 层/组件               | 实现方式                              | 具体选型                                                             |
| ------------------ | --------------------------------- | ---------------------------------------------------------------- |
| L1 滤波引擎（阶段一）       | 手写状态空间模型 + 现成滤波原语                 | `filterpy`（UKF）或自写粒子滤波（核心循环 <200 行）；方程按 4.2.1 实现                 |
| L1 Neural SDE（阶段二） | PyTorch 原语 + 现成 SDE 求解器           | `torchsde` 做积分引擎；漂移/扩散网络自定义，物理项冻结                                |
| L2 SSM 主干          | PyTorch 实现，参考 S4 对角化核论文但不 fork 仓库 | 自写对角化 SSM 层（HiPPO 初始化 + 零阶保持离散化，核心约 100 行）——三级约束嵌入（4.3.2）的唯一可行方式 |
| 分位数头部与损失           | 纯手写 PyTorch                       | pinball loss、幂律尾惩罚项均为自定义损失                                       |
| 数值底座               | 不重复造轮子                            | PyTorch（autograd 为 PINN 约束前提）、NumPy/SciPy、Pandas                 |
| L0 数据管线            | 复用现有基建                            | 对接 backtrader 回建设施                                               |

**底座选型说明**：PyTorch 优先于 JAX——对现有 Python 基建（backtrader、Pandas 链路）摩擦最小且 `torchsde` 成熟；若后期分钟级推理延迟成为瓶颈，再评估 JAX 重写热路径（属优化问题，非架构问题）。

#### 4.5.4 代码规模纪律

- L1 阶段一（UKF + 场论方程）：核心约 300–500 行——**必须手写**，此即理论本体，无库可代劳；
- L2 SSM 主干：核心层约 100–200 行，训练循环走 PyTorch 标准范式；
- 全系统自有核心代码控制在千行级——代码与参数双小，审计与复现才成立，这是"小模型"定位在工程侧的兑现。

### 4.6 可移植性设计纪律与生产推理路线

#### 4.6.1 部署拓扑（先界定"什么需要移植"）

生产推理链路由三类组件构成，其移植义务各不相同：

| 组件                               | 生产形态                       | 移植义务                                                |
| -------------------------------- | -------------------------- | --------------------------------------------------- |
| L1 UKF 引擎                        | 纯经典数值代码（NumPy），独立 CPU 推理服务 | **无**——不进任何推理图，天然跨平台                                |
| L2 推理前向                          | **唯一的移植对象**：导出为 ONNX 图     | 必须始终保持可导出（本节全部纪律围绕此点）                               |
| 训练流程（PyTorch + torchsde + 自定义损失） | 永不进入生产链路                   | **无**——生产环境只消费权重与导出图；跳过 TensorFlow 后，不存在任何"训练侧重写"任务 |

> 纪律 0：训练代码无移植义务；可移植性设计的全部约束只作用于 L2 推理前向图。

#### 4.6.2 生产推理引擎选型：ONNX Runtime 优先，TensorRT 仅作可挂接加速后端

| 维度   | ONNX Runtime（选定）                     | TensorRT（不直接采用）            |
| ---- | ------------------------------------ | -------------------------- |
| 硬件范围 | CPU/GPU/边缘跨厂商（含 DirectML，Windows 友好） | 仅 NVIDIA GPU，硬锁定           |
| 延迟   | 毫秒级（对分钟级节拍余量 ≥3 个数量级）                | 极致优化，但本系统用不上               |
| 交付物  | 单一 .onnx 文件，可版本化、可校验哈希               | 引擎按 GPU/驱动/CUDA 版本重建，审计负担重 |
| 升级路径 | 可热挂 TensorRT Execution Provider      | 无退路                        |

**判定理由**：① 分钟级节拍下 TRT 的极致延迟优化无边际价值；② TRT 引擎的环境绑定与重建要求与第 6 章全链路可审计要求冲突；③ ORT 保留"ORT+TRT EP"的热切换退路，未来节拍升级无需改架构。**确认：不绕道 TensorFlow。**

#### 4.6.3 双重表示纪律（Discipline of Dual Representation）

L2 SSM 层实现时**必须同时维护两种等价前向形式**：

1. **递归形式**（recurrent scan）：用于训练（低内存、逐步推进、支持不等间隔时间戳）；
2. **卷积/并行形式**（convolutional / associative-scan）：用于导出（无 Python 循环、无数据依赖控制流，ONNX 可完整追踪）。

两者在数学上严格等价（同一线性时不变核），实现纪律：

- 两形式共用同一份参数张量，禁止各自持有副本；
- 每次提交代码时，CI 自动执行**双形式数值一致性测试**：同一输入下两形式输出的最大绝对误差 ≤ 1e-5，失败即拒入主干。

#### 4.6.4 算子隔离纪律

- 所有 ONNX 算子集之外的自定义算子（如特殊激活、物理参数化变换）**必须封装在独立模块**，与标准算子部分物理隔离，使转换断点至多集中于 1–2 个文件；
- 推理前向路径上**禁止**使用 Python 侧控制流（数据依赖的 if/for）、in-place 张量别名、以及 `torch.autograd` 内部 API——这三类是 ONNX 追踪失败的首要来源；
- 导出目标 opset 版本写入评价协议并冻结；升级 opset 视同模型变更，需重新跑数值对齐验证。

#### 4.6.5 导出门禁（Export Gate）——CI 强制项

每次模型代码或参数变更，CI 必须依次通过以下门禁，任一失败即阻断合入：

1. `torch.onnx.export` 成功导出（卷积形式）；
2. **数值对齐测试**：PyTorch 前向 vs ONNX Runtime 推理，同一测试向量集下分位数输出的相对误差 ≤ 1e-4；
3. 导出图静态检查：无 fallback 到 Python 的算子、无动态 shape 警告（分钟级窗口长度固定化）。

#### 4.6.6 量化政策

- **首选 FP16**：精度损失对分位数输出可忽略，体积减半；
- **INT8 审慎**：分位数头部对尾部校准敏感，INT8 校准集的分布偏移会直接扭曲极端分位数（支柱 2 覆盖率因此失真的风险不可接受）。若启用 INT8，必须追加"量化后区间覆盖率复测"并满足支柱 2 判据，否则回退 FP16。

#### 4.6.7 交付与审计

- 每次发版交付物 = { .onnx 文件（含哈希）、权重版本号、训练代码 commit 哈希、数值对齐报告 }，四者绑定存档，满足第 6 章可回溯要求；
- 生产环境升级仅允许整包替换，禁止原地热补丁。

### 4.4 L3 解释与交互层（LLM）

**职责：**

1. **解释界面**：将 L1 状态变量、L2 归因工具输出（SHAP / 积分梯度）与评估结果转译为自然语言解释与结构化报告；
2. **逻辑哨兵**：对系统内部输出做一致性勘误（如：预警信号与状态变量快照矛盾、报告结论与统计检验结果不符），发现矛盾时**标记并触发人工复核**——无权自行推翻；
3. **情景叙述与交互**：生成情景分析文本、监管问询应答草稿、人机问答接口。

**职责边界（硬性约束，写入系统权限设计）：**

| 职能        | 归属             | L3(LLM) 权限  |
| --------- | -------------- | ----------- |
| 生成预测      | L1/L2          | 无           |
| 解释预测的内部原因 | 归因工具 + L1 状态变量 | 仅转译，不生成归因结论 |
| 裁定模型优劣    | 评估管线统计检验       | 无权更改结论，仅解读  |
| 触发人工复核    | L3 可发起         | 仅限发起        |
| 交易执行      | 执行层 + 独立限额风控   | 无任何执行权限     |
| 撰写报告/问答   | L3             | 完全负责        |

**设计理由：** LLM 的解释是叙事而非归因——其输出文本的正确与错误在表面上同样流畅，无可信的内部区分机制。故解释权归属可审计工具，LLM 是信道；评判裁定权归属统计证据，LLM 是转译者。此边界是系统经得起同行评审与监管检验的前提。

### 4.7 前沿技术迁移评估与采纳清单（2026-11 评审）

**评估对象**：Jev（TypeSafe AI "System One" 决策模型，2026-09 发布）、混合专家架构（MoE）、长程 Agent 技术（loop / graph / 长记忆 / 自进化 RSI）。

**采纳标准（三条硬门槛，缺一即拒）**：① 不破坏 ≤1M 参数与千行代码纪律；② 不破坏封存段纪律与全链路可审计；③ 必须能落入消融阶梯（5.2.1 E 组）接受样本外验证。

#### 4.7.2 类型化决策接口（借自 Jev 原语，对接执行层）

L1/L2 对执行层的输出接口统一为三种类型化原语，**接口即合约**，全部带概率且留痕可审计：

| 原语            | 本系统语义                               | 示例输出                                 |
| ------------- | ----------------------------------- | ------------------------------------ |
| Noul（概率型是非）   | 变盘预警：未来 N 分钟内发生临界事件的概率              | P(临界事件, 30min) = 0.78                |
| Choice（候选集分布） | regime 判定：{稳态, 趋势确立, 临界, 危机} 上的概率分布 | {稳态 0.12, 趋势 0.55, 临界 0.28, 危机 0.05} |
| Score（有序评分）   | 风险等级（1–5 有序档）+ 行情级别分位数区间            | 风险 3.4/5；90% 区间 [−1.8%, +2.3%]       |


纪律：接口字段冻结管理，变更视同评价协议变更；禁止向执行层输出任何无概率的点估计。

#### 4.7.3 置信度门控信号路由表

| 信号置信度 | 路由 |
|---|---|
| 高（≥ τ_high） | 进入执行层候选队列，仍受独立限额风控兜底 |
| 中（τ_low ≤ c < τ_high） | 触发 L3 生成即时说明 + 标记观察，不自动执行 |
| 低（< τ_low）或状态变量矛盾 | 降级为仅监控；触发人工复核；连续低置信达阈值则启动模型失效降级预案（第 6 章） |

阈值 τ_high、τ_low 在训练段按校准曲线标定，写入评价协议冻结。

#### 4.7.4 Champion-Challenger 离线自进化纪律（RSI 的合规等价物）

- 任何模型更新（含重训练、结构变更、数据窗口滚动）一律生成**新版本号**，禁止在产线上原地迭代；
- Challenger 必须通过全部五支柱检验 + 导出门禁（4.6.5），且 CRPS/VaR 检验不劣于现役 Champion，方可整包替换；
- 替换后保留 Champion 权重一个完整评估周期作回滚兜底；
- 全流程版本留痕，满足第 6 章可回溯要求。**线上不存在"自进化中的模型"，只存在"经审判后加冕的新版本"。**

### 5.1 总原则

- **样本外是唯一法庭**：走步回测（walk-forward），训练只用 t 之前数据；
- **封存测试段纪律**：预留最终时间段（如最近 12 个月），全程冻结，模型定稿后仅使用一次；二次使用视为变相调参；
- **出题人与答题人分离**：评估代码由独立模块维护，模型开发者不可修改；
- **协议先行**：立项前签署《评价协议》，写死封存段、基准清单、通过阈值，防止事后挪动球门。

### 5.2 五大评价支柱

| 支柱 | 目标 | 方法与工具 | 通过判据（示例，协议中定稿） |
|---|---|---|---|
| 1. 点/分布预测比较 | 证明场论模型非过度参数化 | DM 检验、CRPS、样本外似然比；基准全清单见 5.2.1（含消融阶梯） | DM 检验 p<0.05 且 CRPS 显著优于全部基准 |
| 2. 区间校准 | "行情级别上下界"可信度 | 区间覆盖率、校准曲线、pinball loss | 90% 区间实测覆盖率落在 90%±2% |
| 3. 变盘预警 | 临界预警有效性与时效 | 事件化定义（如 30min 内波动率突破 3× 中位数）；ROC/AUC、命中率/误报率、提前量分布；基准：BOCPD、LPPL、阈值法 | AUC 显著优于基准预警器；方向一致性单独报告、不与临界识别混合计分 |
| 4. 风控承诺兑现 | VaR/ES 可信度 | Kupiec 无条件覆盖检验、Christoffersen 独立性检验、Acerbi-Szekely ES 检验；经济价值：止损/撤单避免损失 − 误触发机会成本 → ΔSharpe、Δ最大回撤 | 三项检验全通过；ΔSharpe 为正且统计显著 |
| 5. 稳健性与元检验 | 拷问 regime 依赖与过拟合 | 跨制度分段评估（危机/震荡/单边）；场论参数 ±20% 扰动的性能衰减；合成数据对抗检验（GARCH/MRW/Hawkes 生成数据上识别生成机制） | 参数扰动下性能平滑衰减；合成数据机制识别正确率达标 |

### 5.2.1 基线与对照组全清单（含消融阶梯）

**组织原则**：基线不按流行度罗列，而按**归因逻辑**组织——每条基线负责隔离一个变量，使实验结论能回答"赢在哪"而非仅"赢没赢"。

#### A. 经典计量基线（回答：传统波动率模型够不够）

| 模型 | 隔离的变量 |
|---|---|
| GARCH-X / EGARCH | 条件异方差基线，杠杆效应 |
| HAR / HAR-RV | 已实现波动率的异质自相关（多尺度信息的经典表达——与 RG 粗粒化直接对位） |
| FIGARCH | 长记忆的经典参数化（与场论幂律关联对位） |
| Markov-Switching GARCH | regime 转换的经典方案（与"唯象对称破缺"图景正面对位，**必配**） |

#### B. 随机结构基线（回答：点过程/变点模型够不够）

| 模型 | 隔离的变量 |
|---|---|
| Hawkes 自激发过程 | tick 到达强度与自激发结构（不等间隔事件流的经典主场） |
| BOCPD / 阈值法 | 变点检测基线（支柱 3 专用） |
| LPPL | 临界预警的文献标准（支柱 3 专用） |
| HMM 隐状态 regime 模型 | 离散隐状态路线 vs 本系统连续场论隐状态 |

#### C. 机器学习基线（回答：通用学习模型够不够）

| 模型 | 隔离的变量 |
|---|---|
| LightGBM / XGBoost | tabular 特征工程路线（见 4.5.2） |
| LSTM / GRU | 循环网络基线 |
| TCN | 卷积路线强基线（见 4.3.1） |
| **iTransformer** | 注意力倒置的 LTSF 标杆；硬伤已论证（等间隔假设、非局域先验冲突、无隐状态接口），进组接受数据裁决而非口头排除 |
| PatchTST / TimesNet / DLinear | LTSF 社区代表性基线族（补丁化 / 多周期分解 / 线性极简——DLinear 是"复杂模型是否必要"的试金石） |
| N-BEATS / N-HiTS | 纯深度堆叠基线（可解释基函数变体与场论结构化主张对位） |
| TFT（Temporal Fusion Transformer） | 原生分位数输出的注意力基线（支柱 2 校准比较的正面对手） |
| DeepAR | 原生概率分布输出的自回归基线（**支柱 2 的必配对手**：分布质量比较不能只对点预测模型） |
| 公开竞赛线（M4/M5/M6 冠军方法） | 社区最优水平的绝对标尺 |

#### D. 同族裸架构基线（回答：赢的是 SSM 架构还是场论偏置）——关键组

| 模型 | 隔离的变量 |
|---|---|
| 裸 S4 / Mamba（无物理初始化、无约束损失、无 L1 状态输入） | **架构与偏置的分离变量**：若裸 SSM ≈ 完整模型，则场论偏置无增量价值——这是对本框架最直接的证伪通道 |
| 神经 ODE/SDE（无物理漂移项，纯数据驱动） | 连续时间机制本身的价值 vs 场论方程的价值 |

#### E. 消融阶梯（Ablation Ladder）——本框架自我解剖

| 配置 | 检验的命题 |
|---|---|
| E1: 仅 L1（UKF + 场论方程，零学习组件） | 理论本体的独立预测力（阶段一的直接产出） |
| E2: 仅 L2 裸 SSM（无 L1 任何输入） | 学习架构的独立预测力 |
| E3: L2 + 物理损失约束，但无 L1 状态特征输入 | 约束通道的贡献 |
| E4: L2 + L1 状态特征，但无物理损失约束 | 特征通道的贡献 |
| E5: 完整模型（L1+L2 全耦合） | 全方案 |
| **判读逻辑** | E5 必须显著优于 E1–E4 全部，且 E1 必须优于 A 类经典基线——前者证明耦合必要，后者证明理论本体有效。任何一环失败，对应章节的设计主张降级 |

#### F. 分布预测专项对手（支柱 2 专用）

DeepAR、TFT、分位数 GBDT、GARCH 分位数法——区间覆盖率与 pinball loss 的比较只允许在这组原生概率模型间下结论，避免"拿点预测模型的外挂分位数当对手"的口径争议。

> 纪律：基线清单的增删视同评价协议变更，须经版本评审并记录理由；D/E 两组（同族裸架构与消融阶梯）为**不可删除项**——删除它们等于放弃自我证伪能力。

| 通用 LLM 评测 | 本体系 |
|---|---|
| 保密题库 | 封存测试段（单次使用） |
| 标准答案 | 未来真实数据（走步回测） |
| 排行榜分数 | DM p 值 + CRPS + 覆盖率 + ΔSharpe |
| 公开对照模型 | 六组基线 + 消融阶梯（见 5.2.1：经典计量 / 随机结构 / ML 族 / 同族裸 SSM / 消融配置 E1–E5 / 分布预测专项） |
| 人工评审 | 经济价值货币化核算 + 人工复核触发机制 |

## 6. 监管与合规设计

1. **可审计性**：全部信号、参数、数据版本留痕，满足算法交易报备与事后追责要求；任何一次交易动作可回溯至具体数据版本、模型版本、信号链路。
2. **解释义务**：L3 报告必须附带其证据链（引用的状态变量值、归因数值、检验结果），杜绝"无出处的流畅叙述"。
3. **人在回路**：L3 触发的复核、评估协议变更、封存段解封、执行限额调整，均需人工审批留痕。
4. **风险兜底**：执行层独立限额风控不依赖任何模型输出；模型失效（评估指标跌破阈值）时自动降级为纯风控模式（停止信号输出，仅保留风险监控）。
5. **诚实声明**：对外材料必须包含第 1.2 节的定位声明，明示"量子/场论"为数学工具借用，避免误导性宣传。

## 7. 已知局限与风险登记

| 编号 | 风险/局限 | 缓解措施 |
|---|---|---|
| R1 | 方向预测信噪比本质极低，变盘方向准确率有限 | 只承诺临界识别与区间估计，方向一致性仅作观察指标 |
| R2 | 场论模型参数多于经典模型，存在过度参数化风险 | 支柱 1 的显著性检验 + 支柱 5 的参数扰动测试强制证伪 |
| R3 | "对称破缺/序参量"为唯象定义，非 Goldstone 定理意义严格破缺 | 术语全文统一加"唯象"限定；操作化定义冻结管理 |
| R4 | LLM 解释存在幻觉风险 | 第 4.4 节硬性边界 + 证据链强制引用 + 逻辑哨兵仅可发起复核 |
| R5 | 非平稳市场下模型 regime 漂移 | 支柱 5 跨制度评估 + 失效自动降级机制 |
| R6 | 多重检验与回测过拟合 | 封存段单次使用纪律；Bonferroni 校正 |
| R7 | 计算延迟限制实盘节拍 | 明确分钟级定位；场论推断采用滤波近似而非全路径积分 |
